# Claude Reviewer Backend (`dispatch-claude`)
Read this when you are about to override `CLAUDE_DISPATCH_BARE` or the Claude model or effort, when `dispatch-claude` fails preflight or exits nonzero, when stderr shows a `MODEL-*` line, when the dispatcher handle is lost, or when the user asks for scheduled heartbeat monitoring.

## Auto-terminal Claude backend (cross-vendor reviewer, opt-in)

This cross-vendor backend swaps the usual roles: **Codex (or the user) implements, headless Claude Code (`claude -p`) reviews.** Use when Claude is preferred as the reviewer voice, the human orchestrator runs Codex as the primary implementer, or in the fungibility case where Codex cannot review its own work. The Claude backend is **opt-in only**, through Path selection in `SKILL.md`.

Dispatch detail, all handled inside `dispatch-claude` (no caller change):

- **Probe**: `claude` on PATH (override via `CLAUDE_BIN`); no fallback binary.
- **Deployed-script release**: Before it creates dispatch state or starts a preflight, `dispatch-claude` re-executes from a private temp copy. `IMPLEMENT_REVIEW_DISPATCH_REEXEC` prevents a loop, and `IMPLEMENT_REVIEW_DISPATCH_SOURCE_DIR` retains sibling-script lookup at the deployed source directory. The wrapper removes the copy and propagates the child exit status.
- **No-model preflight**: `CLAUDE_PREFLIGHT=auto` (the default) runs `claude auth status --json` for the official CLI and skips opaque wrappers. API-key, gateway, Bedrock, Vertex, Foundry, and bare modes use `claude --version` as an availability probe because first-party login state does not describe those credentials. `force` applies the probe and strict postflight checks to a wrapper; `off` skips the probe. `CLAUDE_PREFLIGHT_TIMEOUT_SECONDS` sets the positive-integer timeout, default 60 seconds. A rejected preflight exits 70, or 124 on timeout, before a model request is sent.
- **Invocation**: `claude -p --permission-mode bypassPermissions --tools default --add-dir <staged-snapshot> --setting-sources project,local --model <M> --effort <R> --session-id <uuid> --strict-mcp-config --mcp-config <state-dir>/empty-mcp-config.json --output-format text`. This gives Claude the same unattended test, experiment, shell, write-tool, and web-verification capability as the other reviewers. The empty MCP config is still required for cross-agent review: a user-level Codex MCP server must not auto-start inside the Claude reviewer backend, or the reviewer can recurse into Codex and hang with empty output. Excluding user settings also keeps user-level hooks out of the headless review path. The registry names the reviewer's model `<M>` and effort `<R>`, and a registry that cannot answer exits 70. `CLAUDE_CODE_EFFORT_LEVEL` outranks `--effort` and a Claude parent hands its own value down, so the dispatcher sets it to `<R>` in the child too. `--session-id` lets the dispatcher read the actual run back into `review-model`, as the Configuration boundary in [codex-backend.md](codex-backend.md) describes. `CLAUDE_DISPATCH_BARE=1` may opt into `--bare` only in environments that provide `ANTHROPIC_API_KEY` or an explicit `apiKeyHelper`; do not enable it by default because Claude Code 2.1.153 disables OAuth and keychain auth in bare mode. No `--sandbox` flag (Codex-only). The long prompt is fed via stdin, but `dispatch-claude` first wraps it in a relay prompt. This embedded diff covers every staged path, because the dispatcher has no scope argument; use the Claude backend only when the entire staged set is in scope. The dispatcher exports the Git index to `<state-dir>/staged-snapshot` with `git -c core.longpaths=true checkout-index -a` and launches Claude from that directory; if export fails or the directory is not a git worktree, it falls back to the original working directory and records the reason in `git-diff.stderr`. The relay permits tests and experiments, including generated-file writes inside the disposable snapshot, while forbidding commit, push, publish, external-system mutation, and destructive cleanup. The dispatcher writes Claude stdout to `Review-Claude-Code.md`; stderr remains in `<state-dir>/tail.stderr-tmp` for diagnostics. On save, the dispatcher trims any preface before `<!-- Round N -->`; if Claude omitted the marker, the dispatcher inserts it so Phase 2 intake has a stable first line.
- **Supplied inputs**: the snapshot holds only the exported index, so the round checklist (step 4) gives the rule for inputs the index lacks.
- **Live tails and transport rejection**: stdout and stderr flow into `<state-dir>/tail` and `<state-dir>/tail.stderr-tmp` while Claude is running, so `stall-watch` sees liveness before process exit. After a nominal exit 0 from an official or forced run, known authentication, API, stream, connection, timeout, rate-limit, and overload errors in stderr write `<state-dir>/transport-failure`, reject the review, and exit 70.
- **Atomic publication**: Claude stdout stays in the state directory until the process exits successfully. The dispatcher builds and validates a candidate beside the expected review file, then uses a same-directory rename or replacement. Auto-watch therefore sees the old review or the complete new review, never a partially written target.
- **No embedded-diff retry.** The primary Claude relay already includes the staged diff, so the Codex retry pattern for narrowed sandbox failures (see [codex-backend.md](codex-backend.md)) is not applicable.

State-dir, stdout contract (`STATE-DIR <abs-path>` single line), state files (`pre-mtime` / `timestamp` / `tail` / `tail.stderr-tmp`), and the `stall-watch` launch match the shared dispatch contract in section 1c of `SKILL.md`. For Claude, tail growth supplies liveness; the Codex-only terminal suffix is not a Claude completion record.

## Codex waiting for the Claude backend (App and Terminal)

**Scope:** This subsection, and standing rule A of the round checklist of `SKILL.md` that holds the waiting procedure, apply only when Codex is the coordinator and Claude Code is the current reviewer. They override conflicting waiting instructions elsewhere only for that pair, in Codex App or Terminal. Other coordinator/reviewer pairs keep their existing dispatch, waiting, health-check, and failover behavior. In a mixed `/vet claude agy` queue, apply both to the Claude slot only; handle the Agy slot under the existing rules. Under Codex, `/vet both` resolves to that queue. When the retained handle is lost, no dispatcher exit can be read, so resolve the slot with the `await-review.py` command of round checklist step 6 at the original deadline and never stamp a new one; a long-running resolver alone cannot see a dispatcher exit without publication.

If the user selects scheduled background monitoring and this host exposes thread heartbeats, use the requested interval instead of concurrent active-turn polling. Confirm registration and save the repository, round, Claude state directory, original deadline, reviewer queue, and unconsumed tool handles before returning an explicitly pending status. Each wakeup uses `await-review.py --timeout 0` and consumes available dispatcher completion status. Stay quiet on unchanged `ALIVE` or `STALL`. Heartbeats are an optional host-specific handoff; do not assume Terminal provides them or promise automatic resumption without a registered mechanism. A background hook alone cannot provide that handoff: [its completion does not start a new turn](https://learn.chatgpt.com/docs/hooks#how-background-hooks-run).
