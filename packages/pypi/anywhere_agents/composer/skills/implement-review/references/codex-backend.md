# Codex Reviewer Backend (`dispatch-codex`)
Read this when you are about to raise `CODEX_DISPATCH_REASONING` or the timeout, or to override `CODEX_DISPATCH_MODEL`, `CODEX_DISPATCH_SANDBOX`, or `CODEX_DISPATCH_ISOLATE_MCP`; or when a Codex probe fails, stderr shows a `MODEL-*` line, or a fresh Codex review or `FAIL check-10` shows it could not run `git diff`.

## Auto-terminal path (opt-in, codex exec subprocess)

When the user opts in via the trigger rules in Path selection (under Codex Channels), Claude Code dispatches Codex via `codex exec --sandbox danger-full-access` as a background subprocess. The dispatch script writes the prompt to a per-dispatch temp file under `$TMPDIR`, feeds it on stdin (`codex exec -`), and emits a state-dir path to stdout for Phase 2 to consume. Codex writes its review to `Review-Codex.md` per the save contract; the same Phase 1d auto-watch fires on file appearance.

**Trust model and the sandbox flag**: Auto-terminal aligns its trust model with Terminal-relay by passing `--sandbox danger-full-access` to `codex exec`. In Terminal-relay the user is typing into their own Codex window with full fs / network / shell access; in Auto-terminal Claude Code starts the same Codex on the user's behalf, so granting the same access keeps the two channels behaviorally equivalent. Scope discipline (review-only, save findings to `Review-Codex.md`, no commits / pushes / branch operations) is enforced at the prompt level, identical to how Terminal-relay enforces it. For CI / shared / multi-tenant environments where this trust posture is too broad, set `CODEX_DISPATCH_SANDBOX` to a stricter mode (`workspace-write` / `read-only`); the dispatch script honors the env var. A stricter mode can block Codex's own git and file tools, which the embedded-diff retry below addresses.

**Backend permission parity**: Reviewer selection changes the model family, not whether the reviewer can validate its claims. Every Auto-terminal backend runs unattended with its backend's broad execution switch: Codex `danger-full-access`, Agy `accept-edits` plus `--dangerously-skip-permissions`, and Claude `bypassPermissions` plus `--tools default`. Each may run tests, experiments, benchmarks, shell commands, and necessary network verification. The review prompt, not a crippled tool allow-list, keeps commit, push, publish, external-system mutation, and destructive cleanup out of scope. Agy and Claude perform potentially write-producing verification in disposable staged snapshots when export succeeds, so ordinary experiment artifacts do not touch the source checkout.

The primary Auto-terminal dispatch preserves the byte-identical prompt invariant with Terminal-relay: the assembled prompt bytes are the same regardless of channel. The extra `-c developer_instructions=...` value is a Codex CLI configuration argument, separate from the review prompt on stdin, so it does not change those bytes. The dispatch script must NOT call `codex exec review`, `codex exec review --uncommitted`, or any other Codex `exec` subcommand, because those carry Codex's own built-in review prompt template which would compete with the skill's lens-aware prompts. The embedded-diff retry described below is the explicit exception: it is used only after a health-checked Auto-terminal run shows that Codex's own shell tool cannot inspect the repo, usually because `CODEX_DISPATCH_SANDBOX` has been narrowed in a CI / sandbox-strict environment, but also for the same class of failure if a future Codex version regresses under the relaxed default sandbox.

The Auto-terminal path requires `codex` on PATH. Probe before dispatch; if absent, warn and take the next probed entry of the Phase 1c failover queue, reaching Terminal-relay only when none is available. Phase 1c's backend-probe step is the single authority for a backend that is absent, as its failover paragraph is for one that failed. A non-zero `codex exec` exit, a timeout, or a stdin-pipe failure is a confirmed failure; route it through the failover queue in Phase 1c, which is the single authority for that destination. Do NOT add a truncated positional-argument fallback, which would break the prompt invariant. A preflight absence never sets sticky downgrade (section 1c of `SKILL.md`). After a confirmed failure it is set only when the failover queue is empty and the round has no healthy review (`failover-and-recovery.md`), and then later rounds default to Terminal-relay until the user re-opts-in explicitly.

**Configuration boundary: the dispatched Codex inherits only the model and effort of the user's `config.toml`, as the last source**. Under the default MCP isolation, the dispatch script passes `--ignore-user-config` and re-passes `-c model=<M>` and `-c model_reasoning_effort=<R>`. The registry (`user/agent-models.json`; see the `agent-models` skill) decides both. `M` is `CODEX_DISPATCH_MODEL` when set, then the registry's Codex reviewer model, then the top-level `model` in `$CODEX_HOME/config.toml` (default `~/.codex`), which bootstrap syncs from the registry. `R` follows the same order through `CODEX_DISPATCH_REASONING` and `model_reasoning_effort`. With no source, the dispatch exits 70 and names the registry. A config value counts only when it is quoted and made of `A-Za-z0-9._:/-`. Under a top-level `model_provider` other than `openai`, the config model is set aside too: isolation drops that provider, and its model names would reach the default one. Such a setup needs `CODEX_DISPATCH_MODEL` or `CODEX_DISPATCH_ISOLATE_MCP=off`. **Effective, not configured**: `<state-dir>/review-model` records the requested model and effort with the source of each (registry, env override, or config), then `actual=<model> <effort> status=ok|mismatch|unknown` from the codex header. `MODEL-MISMATCH` on stderr means the reviewer did not run on the request. Independently of that isolation choice, every dispatch passes a separate `-c developer_instructions=...` argument telling the child reviewer to skip bootstrap and shared configuration refresh commands and to use the configuration already on disk. The child reads the injected `AGENTS.md` chain (Codex discovers one instruction file per directory: `AGENTS.override.md`, then `AGENTS.md`; it does not discover `AGENTS.local.md` or `agents/codex.md` on its own), and Codex injects at most `project_doc_max_bytes` of it, a 32 KiB default that a composed consumer file exceeds. Every dispatch therefore also passes `-c project_doc_max_bytes=262144`, outside the isolation branch, so the whole file reaches the reviewer with isolation on or off; a value set in `~/.codex/config.toml` alone would not survive `--ignore-user-config`. All project instructions in that file, including the agent-style banned-word list and any NSF rules, remain in force. Everything else in `~/.codex/config.toml` is dropped for the dispatched run: `service_tier`, `[features].fast_mode`, a profile's settings, and any custom provider settings. The MCP-isolation fix drops these settings on purpose, which is easy to miss. Set `CODEX_DISPATCH_MODEL` or `CODEX_DISPATCH_REASONING` to change one review, or change the registry for all. To hand the dispatched run the full user config instead, set `CODEX_DISPATCH_ISOLATE_MCP=off`, which is the documented opt-out and also restores the user's MCP servers and plugins.

**Ratchet detail** (the rule is in the round checklist, step 3): the asymmetry is deliberate. An agent choosing how hard to review its own work creates a self-grading loop, and its confidence is highest exactly where a quiet error hides. The levels a model accepts, and the caveat on `ultra`, are under the stdin invocation shape in Script contract invariants below. A higher tier lengthens wall-clock, so size the dispatch timeout as step 5 of the Auto-terminal path in section 1c of `SKILL.md` gives.

**Python interpreter resolution and the verification contract**: Before it creates dispatch state or spends a Codex round, `dispatch-codex` finds a working Python interpreter in this order: `ANYWHERE_AGENTS_PYTHON`; project `.venv` or `venv`; the activated `VIRTUAL_ENV`; active and discovered conda or Miniforge roots and environments; then every `python3` and `python` entry on PATH. A configured but broken `ANYWHERE_AGENTS_PYTHON` is a hard preflight failure. Every candidate must run an isolated probe, return an absolute `sys.executable`, and execute successfully again through the resolved path. The dispatcher writes the absolute path to `<state-dir>/python-interpreter` and includes it in the child `developer_instructions`; the reviewer must use that exact path for Python commands. Resolving nothing at all is a degradation rather than a dispatch failure: the dispatcher warns on stderr, omits the marker file so its absence is unambiguous, tells the reviewer that no interpreter was pre-resolved, and proceeds. The probe exists to keep a reviewer from claiming verification it never ran, and check 10 enforces that independently by refusing a `PASS` or `BLOCK` verdict without a `VERIFIED` status. Reviews also run on repositories whose verification is not Python at all, so a missing interpreter must not make those repositories unreviewable. The verification-status contract itself is in the round checklist (step 7).

**Embedded-diff retry for Codex tool-sandbox failure (sandbox-strict environments only)**: the round checklist (step 7) says when this retry runs and how its findings are weighed; this paragraph is the procedure. The retry exists as a defensive fallback for two cases: `CODEX_DISPATCH_SANDBOX` narrowed to `workspace-write` or `read-only` in a CI or shared environment, and a future Codex version that regresses the same failure under the relaxed sandbox. A tool-sandbox failure shows as a fresh review that quotes an internal sandbox error such as `windows sandbox: runner error: CreateProcessAsUserW failed: 1312`. Generate the diff from Claude Code's shell by running the exact diff command chosen in section 1b, and include it after the normal save contract, summary, lens, focus, and prior findings. Mark the round line with this content: `Round N (RETRY: codex-exec sandbox blocked tool access; diff is embedded inline below.)` Then add this sentence: Do NOT run `git diff` or any shell command -- use the embedded diff as the source of truth. The retry may be larger than the primary prompt; keep it limited to the section 1b in-scope paths and do not include unrelated staged or working-tree content. Run the same dispatch, auto-watch, and health-check sequence on the retry. **Quality caveat**: the retry sees only the embedded diff hunks, not the surrounding file context. Its findings are reliable for hunk-self-contained issues (test coverage gaps, naming, in-hunk regressions) but prone to false positives for claims that depend on non-diff code (e.g., a "this is missing X" finding when X actually exists elsewhere in the file).

**Script contract invariants** (apply to all `dispatch-codex` / `health-check` / `stall-watch` `.sh` and `.ps1` variants):

- **State-dir lifecycle**: created once per logical dispatch by `dispatch-codex` under `$TMPDIR`; kept on any `WARN` or `FAIL` outcome, including a `WARN` the coordinator has inspected and recorded in the round summary, so the user can still inspect it; deleted only after a clean Phase 2 intake. State-dir names carry `<pid>-<nonce>` and are unique across unrelated dispatches. Automatic stream-death attempts reuse the same directory and preserve each failed attempt under `attempt-N`, which keeps the single `STATE-DIR` stdout contract stable.
- **Deployed-script release**: before it creates dispatch state or starts the reviewer, `dispatch-codex` re-executes from a private temp copy. `IMPLEMENT_REVIEW_DISPATCH_REEXEC` prevents a loop, and `IMPLEMENT_REVIEW_DISPATCH_SOURCE_DIR` keeps sibling-script lookup at the original deployed directory. The wrapper removes the temp copy after the dispatch and propagates its exit status. This releases the deployed `dispatch-codex.sh` path before Bash can block a composer replacement.
- **Timestamp units**: all values in `<state-dir>/timestamp` and `<state-dir>/pre-mtime` are **integer Unix epoch seconds**. Every producer writes integers (`date +%s`), and both readers parse with `int()` and reject a float spelling as a state-contract failure, so a fractional value is not a permitted alternative spelling. mtime comparisons happen in UTC; cross-platform stat is the implementer's responsibility. POSIX may use `stat -c %Y` (GNU) or `stat -f %m` (BSD/macOS). **Do NOT write any other epoch unit** (for example 100-nanosecond ticks since 1601); it would break the Health check 2 freshness comparisons.
- **stdin invocation shape**: the dispatcher feeds the prompt file on stdin by redirection (`codex exec --sandbox "$CODEX_DISPATCH_SANDBOX" [isolation args] -c "developer_instructions=..." - < <prompt-file>`). This shell-level redirection preserves the byte-identical prompt invariant. The `--sandbox` value comes from `CODEX_DISPATCH_SANDBOX` (default `danger-full-access`); see the Trust model paragraph above for why. By default the dispatch passes `--ignore-user-config -c model=<M> -c model_reasoning_effort=<R>`; `M` and `R` follow the order the Configuration boundary paragraph above describes. Isolation keeps a user-level Codex MCP server, plugin, or hook from auto-starting inside the headless reviewer and recursing into a nested codex. Set `CODEX_DISPATCH_ISOLATE_MCP=off` to opt out and run with the full user config. Do this if the review needs the user's `service_tier` or a custom `model_provider`, which isolation drops and does not re-pass. Independently of isolation, the dispatcher passes the separate `-c developer_instructions=...` argument before the trailing `-`. That argument suppresses only bootstrap and shared configuration refresh in the child session; it leaves `AGENTS.md` and all other project rules active. Because it is CLI configuration and the prompt still arrives only through input redirection, it does not modify the prompt-file bytes. `--ignore-user-config` is used because the narrower `-c mcp_servers={}` is deep-merged by Codex 0.139 and leaves the configured servers running. It also resets the model and the reasoning effort, so the re-pass carries the review model and effort. Raise `CODEX_DISPATCH_REASONING` for more reasoning, to `ultra` only when automatic task delegation is intended. A model accepts a level only when its entry in `codex debug models` lists it. Re-passing `service_tier` is deliberately skipped: hardcoding the maintainer's tier would make every round fail for a consumer whose account lacks it, so a temp-`CODEX_HOME` sanitizer (config minus the MCP tables) is the documented path to full config-preserving isolation. Neither the `.sh` nor the `.ps1` dispatcher may use command substitution (`codex exec "$(cat <file>)"`) or positional-arg passing of the full prompt.
- **`stall-watch` silence, stream death, and bounded reaping**: the silence threshold is `STALL_THRESHOLD_SECONDS`, default 600 seconds. A no-growth interval writes `STALL <timestamp> tail-no-growth-for-<seconds>s` to `<state-dir>/stall-warning`. Silence NEVER kills a process. Stream-death detection runs only after tail growth, reads only the last 16 physical lines, removes empty lines, and requires the terminal suffix to contain the Codex response URL error followed by `tokens used` as the penultimate non-empty line and a bare numeric final line. A match writes `STREAM-DEATH <UTC timestamp> codex-response-stream-disconnected` to `<state-dir>/stream-death`. The watcher records the dispatcher's start identity and the worker roots' process-creation identities. It may reap only for `stream-death` or `parent-exited`, and only after a recorded worker identity still matches; unrelated processes are never targeted. If `stall-watch` itself errors, it exits silently.
- **Stream-death retry handoff**: `stall-watch` writes `stream-retry-request` before `stream-death`, performs the identity-checked reap, then writes `stream-reap-complete`. The dispatcher waits up to 10 seconds for that completion marker before archiving and retrying. Missing handoff or archive evidence stops redispatch and emits an `AUTO-REDISPATCH-SKIPPED` diagnostic. The configured retry count is a hard bound. Silence never enters this handshake. The bounded retry conditions and the watcher and resolver outcomes that follow are in [failover-and-recovery.md](failover-and-recovery.md).
- **Check 8 breakdown emission**: when Check 8 fires (any TOOL_FAILURE_PATTERNS hits in `<state-dir>/tail` after backtick-code-span exclusion), `health-check.py` emits a per-pattern count breakdown after the marker total so downstream Claude can recognize known-noise shapes without re-grepping the tail. Form: `WARN check-8 N tool-failure-markers breakdown=label1:n1 label2:n2 ...` with labels derived from the longest word run in each pattern, sorted by count descending. The round checklist (step 7) gives the inspection a Check 8 `WARN` calls for; [health-check.md](health-check.md) holds the Check 8 row and the false-positive tuning principle for reading a breakdown.

## Evidence for latency claims

`<state-dir>/tail` is a transcript for a human to read. It has no timestamps, and the reviewer's prose can quote the same error strings that appear in real diagnostics. Counting occurrences in a tail therefore does not measure elapsed time, call count, or failure frequency. For any claim about where time goes, use `~/.codex/sessions/**/rollout-*.jsonl`. Rollout records carry per-event millisecond timestamps and token counts, and a run can be joined to them by session id. A latency claim without rollout evidence should not be acted on.

Two corollaries matter when reading retained tails. A single tail block can represent one call within a parallel batch; repeated material inside that block does not establish several separate calls. When the diff under review includes this skill, the skill's own diagnostic strings appear in the tail as reviewed content. Any cross-tail scan must exclude that case.
