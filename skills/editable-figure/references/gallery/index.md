## Required preference-first design

For Yue Zhao's paper and proposal figures, understanding and imitating the confirmed visual references is the top design priority. Current task instructions, scientific correctness, required output constraints, and an established document palette or figure-series identity still govern. Generic minimalism, palette presets, icon restrictions, and an agent's preferred aesthetic are fallback advice and must not displace the confirmed preferences. For another user, this personal collection remains candidate material until that user confirms it.

Before choosing a composition or drafting a generation prompt, read the dated feedback and any persistent project feedback, then inspect the actual relevant reference images. Select a primary reference suited to the figure's role and any complementary donors. State a short reference-to-design mapping: gallery ID, confirmed quality to imitate, concrete treatment in the new figure, and disliked or irrelevant qualities to avoid. Listing IDs or saying "professional and polished" without this mapping does not complete the step. Use the existing record without asking the author to repeat it. A small revision can reuse the accepted mapping.

Use that mapping to determine composition, visual variety, technical detail, color/form consistency, and domain-object treatment before applying generic defaults. In particular, 14 is a strongly liked overall style donor. Reference 12 supports a large readable ecosystem overview; 10 and 11 support impactful real-world imagery and logos, and 11 also integrates them with technical detail. Use 13 for equations and consistent encodings, and 15 for professional clarity while avoiding its heavy colors. Choose by the current scientific story; the ranking does not make a single layout mandatory for every figure.

Also read [recent workflow feedback](../recent-workflow-feedback.md) for the 2026-10-17 concept-first preference, the Meta central illustration (16), and cross-project reconstruction failures. Meta (16) records strong approval of the center only.

Carry the mapping and available reference images into every authorized generator's brief and into the implementation plan. Actively imitate the approved visual qualities with the current project's own concepts, notation, data, and relevant logos. Before delivery, compare the actual output with the selected images at the target reading size. Verify that the promised qualities are visible and disliked qualities were avoided. A technically correct figure that ignores the confirmed aesthetic mapping needs revision. For a prompt-only deliverable, verify those instructions and references are present in the prompt, without claiming that an ungenerated image was visually checked. Report a necessary departure briefly with its concrete task constraint; do not silently substitute a generic house style. Save new feedback through the update procedure below.

## Grow the record through use

For a new entry, keep an image link or exact source locator, the figure's role, preference status, and the author's actual feedback with its date when known. Add a short interpretation of what to borrow and what should not transfer. Record unknowns as unknowns. A few sentences per image are sufficient; no scoring system or minimum collection size is required. Prefer one inspection preview around 2000 pixels on its long side, with a compressed format suited to the content. Keep an original PDF when its vector text or fine details support closer inspection. The initial collection retains its supplied originals and previews for that purpose.

Before designing in a consumer, read `figure-preferences/index.md` at the consumer repository root when present and any other gallery location named in local instructions. Newer explicit feedback overrides the affected dimension in the bundled record, within the scope the author specified. When the canonical source is accessible within the task's authorized workspace, merge the saved entry there, preserving its date and project context, and mark the project entry as merged. Otherwise keep it as a pending entry and report the need for a later merge. A merge into the source does not imply that other projects have already received it; shared distribution still requires commit, sync, and bootstrap.

When updating the canonical gallery, maintain `sources.json`, this table, and `preferences.md` together. Keep stable numeric IDs; append new ones without renumbering existing entries. Each source record includes `id`, `title`, `role`, `copied_file`, `preview`, and the original's `sha256`. Confirmed feedback uses a matching `## NN Title` heading and one or more `**作者反馈：** ` paragraphs in `preferences.md`; an entry without feedback remains a candidate. Keep each feedback paragraph on one physical line, separated from the next block by a blank line. Append follow-up feedback under the same heading as another `**作者反馈：** ` paragraph beginning with its date. Preserve earlier context, and identify which dimension a correction supersedes. Run `python scripts/build_gallery.py` from the skill directory to regenerate `index.html`, then run `python scripts/build_gallery.py --check`. The page's count, cards, and feedback come from these records. Newly dropped images must be registered as candidates before regeneration; the check reports unregistered PNG, JPG, and PDF files. `gallery-9-figures.html` is only a redirect to the current index, retained for the existing bookmark.

Useful distinctions include composition, domain-object treatment, information density, typography, color, and illustration style. Record only the dimensions supported by feedback. A preference can be specific to a paper, proposal, or figure role rather than a global rule.

After the author selects a draft or requests a meaningful correction, retain the relevant version and feedback in the canonical gallery or the persistent project location described above. A before/after pair is useful when it shows a concrete preference, such as replacing prose with a scene or making one panel dominant. Label disliked examples or features only when the author says so. Avoid collecting every intermediate export.

Before designing, choose relevant examples by figure role and state which qualities will transfer. Pass those examples and qualities to each authorized image generator through the common brief described in [hybrid-figures.md](../hybrid-figures.md). The new figure still needs its own scientific story and source checks.

Current instructions and the destination document take priority over historical preferences. When feedback changes, update the affected dimension and retain context rather than accumulating contradictory universal rules.
