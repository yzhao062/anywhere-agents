For new paper/proposal overviews, standalone mechanism figures, and substantial redesigns, explore visual expression before committing to PowerPoint geometry. For Yue Zhao, an actual whole-figure generated concept is the default starting point after source and reference analysis. Recommend two independent image-generating agents when authorized; one authorized generator can complete the default concept stage. A native wireframe may help check semantics, but does not replace the generated visual draft for Yue Zhao's paper/proposal overview and standalone-mechanism workflow. ## Select a Primary Composition and Specific Contributions

Compare candidates against the source and at the intended document width. First require scientific correctness and the requested output constraints, then treat fidelity to the selected preference mapping as the leading design criterion. Check the actual images against their references for meaningful technical detail, visual variety, and color/form consistency. Reject a generic clean candidate that misses the confirmed aesthetic. Also check reading order, occupied space, legibility, and reconstruction effort. A polished image can still contain a false dependency, duplicated object, misplaced variable, or invented result. Correct those defects before carrying its composition forward.

Select one primary composition and name any specific elements borrowed from another candidate when one exists. Keep one integration owner to maintain consistent geometry and wording. Other requested agents can review the result without independently overwriting the master. Concept generation explores visual options; it does not require two competing PPTX implementations or an additional review panel.

Record the selection in a short working note, for example: primary layout from candidate A, hardware treatment from B, labels from the manuscript. If B only informed comparison, describe that role accurately. Do not claim a combined figure unless identifiable contributions from both candidates survive. Keep the stronger composition intact rather than averaging incompatible layouts.

Compare the reconstructed figure beside the selected concept. Preserve its useful hierarchy, object detail, and visual flow unless a semantic or print-size correction requires a change. Rebuilding every detail as simple native geometry can erase the visual strengths that motivated the selection. Use the picture boundary below instead of measuring success by the percentage of native objects.

Record a short keep-list before rebuilding: the focal object or scene, its internal detail, useful depth or layers, meaningful technical glyphs, and color-to-object mapping. Compare the generated concept, native export, and selected reference at the same reading size. If the export has become mostly uniform boxes and prose, restore the missing visual content before delivery. Matching colors and panel count alone is insufficient. Keep necessary semantic corrections explicit; generated formulas, dependencies, and plots are not scientific evidence.

Feedback such as "childish", "busy", or "AI-like" does not by itself request monochrome styling, flat objects, or removal of illustration. Locate the specific issue in the visible artifact and preserve liked regions while correcting hierarchy, excess text, competing accents, or tangled arrows. The Meta revision in [recent workflow feedback](recent-workflow-feedback.md) shows why replacing rich technical objects with prose can make a technically reviewed figure unacceptable to the author.

## Keep Pictures at the Object Boundary

| Content | Representation |
| --- | --- |
| Hardware, instruments, domain illustrations, or other detailed object appearances | Independently replaceable pictures when their detail helps understanding |
| Diagram labels, panel titles, research questions, section pointers, and symbolic marks | Native text or shapes |
| Arrows, dependency edges, permission marks, boundaries, partition marks, and communication links | Native shapes, connectors, or editable curves |
| Authentic screenshots, photos, and measured plots | Preserve the source artifact and disclose its picture boundary; keep added annotations native |

Intrinsic text inside an authentic screenshot can remain part of that evidence. Diagram labels overlaid by a generator, such as actor names or a research question, belong in native objects. A scientific plot retains its data and plotting workflow; tracing it into decorative native lines does not make its data editable.

Extract the smallest useful object. A whole scene crop containing devices, text, permission symbols, and connecting arrows bakes the figure's logic into pixels. It also creates mismatched typography and line styles when joined to native regions. After selecting the composition, obtain an object-only asset or asset sheet before insertion, removing diagram text, arrows, links, and semantic symbols through the available image-editing workflow. Then insert the objects separately and reconstruct those semantics in PowerPoint.

Inspect the actual asset before cropping. Check object edges, halos, residual strokes, unwanted labels, and opaque background bounds. When text or a line overlaps the object, a tighter rectangle or a white cover usually leaves an incomplete asset. Clean or regenerate the object before insertion. If extraction remains unsuccessful or image editing is unavailable, reconstruct that object natively while retaining the surrounding composition. Re-render the composition to catch picture backgrounds covering native connections.

Name the pictures by role and retain their source or generation record. Group each object with its editable labels when helpful, while preserving independent selection. For detailed assembly and curve checks, use [native-powerpoint.md](native-powerpoint.md).

## Unify Relationships and Use Space Well

Use the manuscript's palette and one typography and line system across the entire figure. Apply consistent arrowhead size, stroke weight, and dash meaning. Rich object art can coexist with simple native labels when scale, contrast, and connection ports are coordinated.

Choose curves where they improve the reading path, with smooth bends and deliberate start and end tangents. Use attached connectors where node movement must carry the edges. Static native curves remain editable through control points, but require manual rerouting; disclose that behavior. Avoid long detours, awkward forks, collisions, and inconsistent endpoint contact.

Recover space through reflow, closer related groups, and a canvas that fits the composition. Preserve meaningful gutters and readable printed labels. See [space-efficiency.md](space-efficiency.md); a particular case's canvas reduction is not a universal density target.

## Carry the Selected Version into the Document

Identify the current editable master and distinguish original concepts, comparisons, and publication exports by meaningful filenames. Keep every generated original beside the figure source, outside temporary storage, so the selection can be re-examined later. After manual edits, record whether the builder still reproduces the master. For several coexisting variants, a short note mapping master to exports and document inclusion path is sufficient; add hashes when needed to distinguish otherwise ambiguous files.

Use this handoff when document insertion is authorized:

1. Export the final editable master through native PowerPoint to PDF and a preview.
2. If the destination needs another format, derive it from that export and inspect the conversion. Keep text and geometry vector where the format supports them; identify remaining raster assets accurately.
3. Resolve the document's actual included file, including wrappers or conversion steps, and confirm it points to the selected export.
4. Compile the current document, render the page containing the figure, and compare it with the native export at publication width. Check labels, object placement, arrows, caption, and surrounding pagination.

When the user reports an old figure, inspect the included asset and compiled page before attributing the mismatch to caching. A fresh filename can help a stale viewer only after the underlying document contains the correct figure. Renaming an incorrect export does not repair source selection.

## Report What Was Checked

Keep scientific fidelity, visual quality, and editing behavior separate. Use the main skill's image-only first-read check when a requested reviewer is assessing comprehension. Follow it with the caption and source for semantic review. Native shape counts, a successful build, or another model's approval do not prove that the labels edit or the connectors follow nodes.

Test representative native labels and symbols throughout the figure, including regions built around pictures. Move an independent picture, edit a native curve control point when used, and move an attached node when attachment is promised. Perform these checks on a disposable copy and inspect the result. Deliver the master and its matching preview, stating which objects remain pictures and which curves need manual rerouting.

Case basis: a September 2026 ARO overview compared two generated originals and then used detailed hardware objects with native labels and relationships. An earlier whole-scene crop retained baked-in text and links, which the author rejected. The subsequent revision recorded separate picture movement, label edits, curve-control edits, and attached-connector movement. Those checks support the editing workflow; they do not establish author acceptance of the final appearance or a general ranking of image generators.
