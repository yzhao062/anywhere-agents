# Agy Reviewer Backend (`dispatch-gemini.py`)
Read this when you are about to override `ANTIGRAVITY_DISPATCH_MODEL`, `ANTIGRAVITY_DISPATCH_EFFORT`, or `ANTIGRAVITY_PREFLIGHT`, or to run `--print-model`; or when an Agy dispatch exits 2, 70, or 124, stderr shows a `MODEL-*` line, or Check 8's `breakdown=` includes `recovered:`.

## Auto-terminal Agy backend (Gemini through Antigravity CLI, opt-in)

The Agy backend gives the review loop an independent Google model family. It runs the official Antigravity CLI in headless mode. Use `agy` as the canonical reviewer token; `gemini` and `antigravity` remain accepted aliases. Path selection (under Codex Channels) says when the channel and reviewer defaults select it.

The dispatcher is `dispatch-gemini.py`, run as `<python> dispatch-gemini.py` with the flags that the round checklist (step 5) and section 1c (Send to reviewer) give. It handles these details:

- **Binary resolution**: prefer `ANTIGRAVITY_BIN`, then `agy` on PATH.
- **Default reviewer family**: the registry's Agy reviewer row decides (see the `agent-models` skill): a family stem, an effort tier, and a fallback chain, read into `DEFAULT_MODEL`, `DEFAULT_EFFORT`, and `FALLBACK_MODELS`. The preflight's `agy models` listing supplies the newest version of that family in the tier, so a new release needs no edit. An account that lists no member of the family falls back to the newest member of the first fallback family it lists: the row's own, then the family row's (a row with no fallback stem fails instead), recorded as a `MODEL-FALLBACK ... reason=template-unlisted` line on stderr. When `ANTIGRAVITY_DISPATCH_EFFORT` is unset, the effort follows the chosen slug's tier, because Agy rejects a conflicting `--effort`. A `MODEL-RESOLVE from=... to=...` line on stderr records the switch. With `ANTIGRAVITY_PREFLIGHT=off` there is no listing, and the slug runs as written. A model named in `ANTIGRAVITY_DISPATCH_MODEL` runs verbatim and never falls back; `ANTIGRAVITY_DISPATCH_EFFORT` overrides the effort. When the registry cannot answer and those two do not cover it, the dispatch exits 70 and names the registry. The dispatcher passes `--log-file <state-dir>/agy.log` and records the request and the logged model label in `review-model`, as the Configuration boundary paragraph of [codex-backend.md](codex-backend.md) describes.
- **Model lookup**: `<python> dispatch-gemini.py --print-model` prints the slug and effort a round would run on, separated by a space, then exits. It needs no staged diff and applies the same environment overrides and preflight; a preflight failure exits with the code a dispatch would return. A skill that calls Agy directly passes those two values as `--model` and `--effort`, which keeps its reviewer on the `/vet agy` model. Without `--model`, Agy uses its interactive default model instead.
- **Preflight**: `ANTIGRAVITY_PREFLIGHT=auto` checks `agy --version`, `agy models`, authentication, and exact model availability before spending a review request. `force` has the same behavior for wrappers; `off` skips it. `ANTIGRAVITY_PREFLIGHT_TIMEOUT_SECONDS` defaults to 60. Exit 124 is a preflight timeout. Exit 2 is a refusal before anything is spent: the self-review guard, a missing prompt file or review directory, or staged-path drift. Exit 70 covers a rejected preflight, a registry that cannot answer, and a rejected result status. Route any of them as a confirmed failure under section 1c.
- **Executable verification**: the dispatcher exports the Git index to `<state-dir>/staged-snapshot`, appends `git diff --cached --no-ext-diff` to a relay prompt, and runs Antigravity with `--mode accept-edits --dangerously-skip-permissions --add-dir <staged-snapshot>`. Agy's tool shell starts in its own scratch directory even when the process `cwd` points elsewhere, so the relay names the exact snapshot path as the place for source-file tools and verification commands and requires shell commands to change to it first. The relay also states that the embedded diff is the review input, so the reviewer does not obtain a second copy from the snapshot or `git diff`, and that unrelated `.gemini` and `.system_generated` material is skipped. Gemini can run tests, experiments, benchmarks, shell commands, and network verification, including tools that create normal generated artifacts inside the disposable snapshot. It must not recreate files from the embedded diff if snapshot access fails; that condition is a blocked verification. The prompt still forbids commit, push, publish, external-system mutation, and destructive cleanup. Gemini is never given the original worktree as an added directory: an unsuccessful diff capture, Git-root lookup, or snapshot export aborts the dispatch and records the reason in `git-diff.stderr`. The whole index is exported on purpose: the snapshot has to stay a working copy the reviewer can run the repository's own verification inside, not only the changed files. The dispatcher deletes the snapshot when it exits, whatever the outcome of the round, and leaves the rest of the state directory in place.
- **Supplied inputs**: the snapshot holds only the exported index, so the round checklist (step 4) gives the rule for inputs the index lacks.
- **Long-prompt transport**: the relay goes over NDJSON stdin with `--input-format stream-json --output-format stream-json`. `ANTIGRAVITY_DISPATCH_TIMEOUT_SECONDS` defaults to 2700 and is passed as `--print-timeout`.
- **Atomic publication**: Antigravity returns the complete review in its final result event. The dispatcher normalizes the current round marker, validates a substantive response, and atomically publishes the backend-stable `Review-Antigravity.md`. Stdout remains the single `STATE-DIR <abs-path>` line; model events and errors stay in `tail` and `tail.stderr-tmp`.
- **Result status**: after the CLI exits 0, an explicit, nonblank result status other than `SUCCESS` is rejected with exit 70, unless the recovery below applies. A missing or blank status keeps the legacy success behavior. Antigravity exits 0 when it stops on a quota limit, and that event still carries the model's opening narration, which would otherwise become the round's review. The recovery covers a response with review structure. That structure is this round's marker on its own line, followed by a standalone `Verification status:` line and a labeled verdict, the lines the health check reads. Lines inside closed triple-backtick blocks or single-line inline code do not count, the same exclusions the health check applies. A tilde fence or an unclosed fence is not recognized as quoted code. A server error such as `UNAVAILABLE (code 503)` can end a run after the review is written. Such a response is published, and the dispatcher names the error on stderr and in `<state-dir>/backend-failure`. The structure makes a recovery candidate. It is not a complete Markdown parse, and it does not show the findings are finished. Check 8 shows a recovered review as `recovered:` in its `breakdown=`; the round checklist (step 7) says how to inspect it.
- **Expected duration**: a review of a large diff often takes 15 to 25 minutes, because Agy builds and tests inside the snapshot and its tail can stay silent for minutes at a time. A `STALL` at 600 seconds, or `ALIVE` from `await-review`, is expected in that window. Keep waiting until the round deadline.
- **Residual-process guard**: the shared `stall-watch` starts with its working directory inside the state directory, not the reviewed repository. If the dispatcher disappears, the watcher uses its existing identity-checked parent/worker contract. Silence alone still never kills a reviewer.

The old `gemini` CLI is not this backend. Personal Google AI Pro and Ultra subscription access is routed through `agy`; using a Gemini API key or a Google Cloud project is a separate billing path.
