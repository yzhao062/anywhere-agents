# Changelog

All notable changes to `anywhere-agents` are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Version tags apply uniformly to the repo content **and** the matching `anywhere-agents` PyPI / npm packages — they share one release stream. Consumers pinned to a specific tag get a stable snapshot; consumers on `main` receive ongoing updates.

## [Unreleased]

### Fixed

- **`prun` Agy units no longer raise a Windows UAC prompt.** `dispatch-task-agy.py` passed Agy's `--sandbox` on every unit. On Windows that sandbox starts an elevated admin broker (`agy --exebox-admin-broker`). Each unit that ran a shell command therefore popped a User Account Control dialog, and declining it failed the command. Now the dispatcher omits the `--sandbox` flag. `PRUN_AGY_SANDBOX` controls whether it is added: `1`/`true`/`yes`/`on` add it, `0`/`false`/`no`/`off`, empty, or unset omit it, and anything else exits 2 before launch. The variable does not disable a sandbox enabled in Agy's own settings (`enableTerminalSandbox`). Units keep the web, the shell, and file writes through the unattended `accept-edits` default, matching the `/vet` Agy reviewer, which never passed the flag. Scratch directories and throwaway clones reduce accidental changes to the working repository. They do not enforce filesystem or network isolation, so the worker must follow the prompt's ban on commit, push, and destructive git.
- **The session banner no longer reports the bundled `agent-style` pack as undeployed.** Session Start Check item 7 now seeds the bundled defaults and resolves their identity from `pack-lock.json` before comparing against user-level rows, the way `anywhere-agents pack verify` does. The `agent-style` row that `pack add` writes on first use therefore stops counting as a gap in every project that relies on the bundled default.

## [0.8.0] — 2026-09-11

### Added

- **`prun` now spends Sonnet and Agy quota, not Codex quota.** Sonnet keeps the units that need session tools, while the new `dispatch-task-agy.py` path runs `gemini-3.8-flash-high` at `high` effort through the authenticated Antigravity CLI. Codex is reserved for the no-argument `/vet` gatekeeper role because its current credit cost makes it a poor bulk fan-out pool. Agy units retain the existing `STATE-DIR`, monitor, fresh-result, atomic-publication, and fallback contracts. Units run unattended (`accept-edits` plus `--dangerously-skip-permissions`) inside a per-unit scratch directory or a throwaway clone; `--mode plan` is the read-only opt-in. The dispatcher uses Agy's bounded print timeout and never scans for or terminates unrelated agent processes. Legacy Codex dispatch scripts remain packaged only for compatibility with existing state and recovery tooling, but current routing never selects them. Parallel width remains task-shaped: there is no two- or three-worker product cap.

- **`implement-review` gains an Antigravity-backed Gemini reviewer.** With Auto-terminal selected, `/vet agy` is the canonical invocation; `/vet gemini` and `/vet antigravity` remain aliases, and bare `/vet` keeps Codex as the default. Tested with Antigravity CLI 1.2.0, the backend defaults to `gemini-3.8-flash-high` at `high`, the highest effort that release exposes for the model, and uses the backend-stable `Review-Antigravity.md` output name. Model and effort remain overridable through `ANTIGRAVITY_DISPATCH_MODEL` and `ANTIGRAVITY_DISPATCH_EFFORT`. Reviewer permissions are now capability-consistent across Codex, Agy, Copilot, and headless Claude: each can run tests, experiments, shell commands, and necessary network verification without interactive approval.

  `dispatch-gemini.py` resolves the official `agy` binary, including the Windows user-path location an already-running shell may not yet see, then checks version, authentication, and exact model availability before the review request. It exports the staged Git index to an isolated snapshot, embeds the staged diff in an NDJSON stdin prompt, and runs `--mode accept-edits --dangerously-skip-permissions --add-dir <staged-snapshot>`; a failed diff, Git-root lookup, or snapshot export aborts rather than falling back to the original worktree. The relay names the exact path because Agy's tool shell otherwise starts in its own scratch directory. Experiment outputs remain disposable, while the prompt forbids commit, push, publication, external-system mutation, and destructive cleanup. The final response is validated and atomically published. The existing stall watcher observes it without treating silence as permission to kill a reviewer, and the self-review guard rejects Agy, Gemini, or Antigravity as both coordinator and reviewer.

- **The quota surfaces now cover Agy and the Claude Code status row is compact.** `agent-quota.py` keeps a readable per-pool Claude / Codex / Agy view. `statusline.py` renders the primary sources as a dense single line. For example: `cc 5h82% 7d38% | gpt 7d75% @now | agy 5h100% 7d100% @now`. It retains reset countdowns and snapshot age. Compact mode drops model-version digits and Agy plan labels to avoid visual collisions; a rolled window says `(reset)` rather than the ambiguous `(!)`.

  Agy exposes separate 5-hour and weekly buckets for Gemini and for Claude/GPT models. The compact status line labels and shows the default Gemini pool as `agy`, avoiding a redundant third-party pool in an already crowded row. The expanded `agent-quota.py` output shows both pools, including the allowance used by Agy's Sonnet, Opus, and GPT-OSS models. Their source is `agy -p "/usage" --output-format json`, a zero-turn metadata query. A lock-protected helper refreshes the disk cache in the background at most once per five minutes, uses a hard timeout, and applies the same cooldown after failure. The status render never waits on that network call and does not inspect or stop any running agent session.

- **`editable-figure` joins the shipped skill set, taking `aa-core-skills` from five skills to six.** It designs a paper, proposal, or README figure and delivers a PowerPoint source whose text, shapes, and connectors the author can still edit. The workflow is analyze, find references, design for one takeaway, build native objects, inspect in context. It covers the editorial decisions only. The authoring runtime comes from whatever presentation tooling the session already has, so the skill does not depend on one model or one desktop plugin.

  It sits beside `ci-mockup-figure` rather than replacing it. That skill captures HTML and code-native figures as images. This one keeps the delivered artifact editable, which matters when a co-author has to change a label six months later and no longer has the builder. `my-router` routes an explicit PowerPoint or editability request here, ahead of the generic figure and README routes. An explicit HTML, TikZ, screenshot, or prompt-only request keeps the format it asked for.

  Three inspection checks are kept separate because they fail independently. Meaning is traced back to the source. Rendering and occupied space are measured at the real publication width. Editability is verified by moving a connected node on a disposable copy; a shape count or a PNG preview establishes none of it.

  **It is the first shipped skill that cannot finish everywhere, and the constraint is a capability check rather than an operating-system gate.** Authoring is not the limit: `python-pptx` and PptxGenJS both write native objects headlessly. Validation is. Nothing on a Linux server, container, or CI job can confirm the file opens, renders, and edits as intended, and that check is what separates a real editable figure from a flattened image. It needs desktop PowerPoint, so Windows or macOS. The bundled `scripts/render_powerpoint.ps1` narrows further, since Windows COM automation has no macOS equivalent.

  The check therefore lives at invocation, in the skill body, rather than in the pack manifest. `hosts:` selects an agent, not an operating system, and no platform key exists to add. An OS test would also pass on a Mac with no PowerPoint installed, which is the state that actually breaks the workflow. Deployment stays host-scoped and the skill refuses the build itself.

  Discovery surfaces carry the caveat so a consumer meets it before invoking: the `description` frontmatter the router reads, the four package and repository READMEs, the pack description, the docs-page admonition, and the router's own rules. A session without the capability explains the limit and offers `ci-mockup-figure`, which covers that case through headless Chrome, TikZ, and skia-canvas. It never silently substitutes an image for a requested PPTX.

  **It ships byte-identical to its `agent-config` original, opinions included.** The skill names three specific papers as the source of its default palette, and three selected figures from the maintainer's awarded proposals as style exemplars, with locators that resolve only on their machine. A sanitized variant was built during this change and then reverted. The palette preference is the content rather than an accident of authorship, and a consumer without the referenced proposals simply has no locator to open, which the exemplar file already accounts for. Dropping the locators bought nothing and cost a permanent BY-DESIGN split plus a manual re-sanitization pass before every future release. `scripts/check-parity.sh` therefore lists `skills/editable-figure` under STRICT with the other four shared skills. `skills/my-router` stays the sole BY-DESIGN skill, because its two copies route to genuinely different skill inventories.

  Fork it and change the palette if you want your own. `references/default-palette.json` is self-contained and holds the exact values the skill reads.

### Fixed

- **The `prun` monitor no longer reads an Agy FALLBACK result as a completed unit.** It matched only the legacy Codex header `result (FALLBACK, worker wrote no result file)`, while the Agy dispatcher writes `result (FALLBACK, Agy wrote no final result)`. A failed unit therefore produced `MONITOR-EVENT all-done` and exit 0, the same signal a caller relies on to mean every unit finished cleanly. Both monitors now match the anchored, case-sensitive producer header `# <unit-id> result (FALLBACK, ` on line 1, so a real result whose first line merely quotes that text stays `done`, with regression tests for the Agy header, the quoted fragment, and the lowercase mention. Observed on a live run on 2026-09-11.

- **`agent-quota.py` names a missing `agy` binary.** On a machine without the Antigravity CLI the plain readout said `Agy (refresh started)` on every run, because the background helper it launched exited 1 without a message and no cache ever appeared. The readout now says `agy not installed` and starts no helper; an existing cache still renders. Found on the ARM64 Linux release gate.

### Changed

- **`prun` Agy units now run with the same unattended capability as the `/vet` Agy reviewer, take the larger share of ordinary units, and can continue a conversation.** The first live runs showed what `--mode plan` cost a unit: request-review mode auto-denies `read_url`, `run_command`, browser tools, and reads outside the unit's working directory in a headless run, so a unit that needed any of them ended in FALLBACK instead of pausing for approval. `dispatch-task-agy.py` therefore defaults to `accept-edits` with `--dangerously-skip-permissions`, so a unit can verify numbers, run experiments, and fetch the web. Safety stays structural, in a per-unit scratch directory or a throwaway clone with no remote, and `--mode plan` remains the explicit read-only opt-in. The unattended default applies only to the scratch directory the dispatcher creates: a caller-supplied `PRUN_SCRATCH_CWD` or `--add-dir` requires an explicit `--mode`, so the write-capable mode is a named choice for any directory the dispatcher did not create, and an empty `--add-dir` or `--continue-from` value fails before launch instead of resolving to the invocation directory or silently starting a fresh conversation. Two flags were added. `--add-dir PATH` (repeatable) puts a clone or snapshot in the unit's workspace without copying it into the scratch area. `--continue-from STATE_DIR` resumes the conversation recorded in the new `<state-dir>/conversation-id` file, so a follow-up turn keeps the earlier context. A worker that writes its own result file no longer loses it: the dispatcher used to replace that file with the final response, which on a live run turned a full trace table into a one-line summary; a non-empty worker-written result is now kept and the final response is stored beside it as `<result>.response.<ext>`. `SKILL.md` now routes session-tool units to Sonnet and the larger share of everything else to Agy, and tells the coordinator to keep the Agy pool busy with follow-up units while slower units finish. Probed against Antigravity CLI 1.2.1: the default mode ran a shell command and fetched a page unattended, `--add-dir` granted a read outside the scratch directory even in plan mode, plan mode still denied `run_command`, and `--continue-from` recalled a value stated only in the earlier turn.

- **The compact status line drops the model name and its emoji prefix in favor of short pool labels.** `cc`, `gpt`, and `agy` replace the earlier model-name labels. Each countdown now carries a leading space, and pools are joined with ` | ` rather than a bare pipe. For example: `cc 5h82% (3h4m) 7d38% (2d17h) | gpt 7d75% (6d3h) @now | agy 5h100% (4h59m) 7d100% (6d23h) @now`. The expanded `agent-quota.py` readout keeps the full names. The row had grown too dense to read at a glance, and the shorter labels paid for the added spacing.

- **The Codex policy in `AGENTS.md` now documents `gpt-5.6-sol` at `standard`, with `fast_mode = false`, as the interactive default.** Codex now serves only as the `/vet` gatekeeper, and GPT-6 Astra bills 2.5x, so the interactive session no longer defaults to the pricier model. Astra with `fast` remains the documented dial-up for a task that earns the extra depth, and the session banner no longer flags Sol at standard as drift. The text also states that the `/vet` Codex dispatcher passes `--ignore-user-config`, so the interactive model configured here never reaches a dispatched review.

## [0.7.18] — 2026-08-22

### Added

- **`/vet` is a short alias for `implement-review`.** The skill is the one typed most often and its name is long. Renaming it was rejected on measurement. The name appears 680 times in the source repo and 503 times here. It is also carried by 26 consumer repositories as a deployed copy, and by both published packages. The `IMPLEMENT_REVIEW_*` environment variables and the dispatch state-directory prefix that `auto-watch` globs for carry it too. The deciding constraint is different: nothing prunes a skill directory that vanishes upstream. Removal happens only through an explicit `pack uninstall`. A rename would therefore strand the old name deployed in every consumer, still answering the old slash command, with content frozen at the release before the rename.

  A pointer costs none of that. `.claude/commands/vet.md` declares `alias-of: implement-review` in its frontmatter and names the target skill's three lookup paths. Both the Claude Code slash surface and the documented lookup order then resolve the same `SKILL.md`. The canonical name does not move.

  The pointer contract learned what an alias is, and learned it narrowly. `tests/test_pointer_files.py` reads the target from the leading frontmatter block only. An `alias-of:` line in the body is not a declaration, because honouring one would let a sentence silently reassign which skill a pointer resolves. Duplicate keys raise rather than pick a winner. Every pointer, canonical or alias, must resolve a skill that exists, so neither kind can dangle after a rename. `vet` is additionally pinned to `implement-review` by name: the generic rules all still pass if an alias is quietly repointed with its lookup line changed to match. `tests/test_repo.py` asked for exact skill-to-pointer equality, which forbids a second pointer outright. It now asks that every skill keep a canonical pointer, and validates lookup text per skill.

  Delivery needed its own fix. The wheel's package data globs `.claude/commands/*.md`, so a new pointer rides along inside the artifact and looks shipped. The composer writes only what the manifest enumerates, though, and only enumerated outputs are lock-owned and removed on uninstall. An unmapped pointer therefore reaches consumers through the source bootstrap's force-copy and never through the package. Both `bootstrap/packs.yaml` copies now map `vet.md`, and `.claude/commands/vet.md` joined the aa-internal STRICT list in both parity scripts. `test_shipped_manifest_deploys_every_command_pointer` asserts that every pointer on disk has a mapping, so the next one cannot fall into the same gap.

## [0.7.17] — 2026-08-22

### Fixed

- **A stopped background task is no longer read as a failed review.** `/implement-review` dispatches the reviewer as a background task and read the harness's task notification as the round's outcome. A notification carrying `killed`, summarized as `Background command "..." was stopped`, describes the harness's task wrapper. The reviewer is spawned detached, so it outlives that wrapper and keeps writing to the same inherited handles.

  Six such notifications arrived on 2026-08-21 across two repositories, and in all six the reviewer was still running: dispatch output still growing minutes later, review files published up to sixteen minutes after the stop. One session read two of them as consecutive dispatch failures, set sticky downgrade for the rest of the session, and stopped. The review it was waiting for landed ten minutes later, complete, carrying a `BLOCK` verdict, and was never read.

  `skills/implement-review/scripts/await-review.py` resolves the round from state-directory evidence instead. It returns `REVIEW-READY` (0), `ALIVE` (3), or `DEAD` (4), plus two non-sticky checkpoints for a person at exit 2: `TIMEOUT` when the round outlived its deadline, and `REAP-UNKNOWN` when a stream death never produced its reap-completion marker. Only `DEAD` counts as an Auto-terminal runtime failure. Replayed against the three real state directories from that day, it returns `REVIEW-READY` for all three.

  Silence stays non-terminal, which is the property the whole script exists to preserve. `DEAD` requires a stream death whose identity-checked reap completed, because a quiet tail proves nothing and `stall-watch` already treats ten minutes of it as a soft signal. A review published under another round's marker is reported and left to the deadline, since a reviewer can publish twice in one round and the second write is the one worth having.

  The round's bound is a file rather than a value in the calling agent's context, which does not survive the stop this change is about. `<state-dir>/round-deadline` is stamped once with an exclusive create, at the round's origin plus 60 minutes, and read back on every later call. The origin is the earliest readable timestamp in the directory: a successful redispatch archives attempt N and rewrites the root `timestamp`, so deriving from the root afterwards hands the round the time attempt 1 already spent. A replay measured 840 seconds of extension without that correction.

  Both `auto-watch` variants now require `stream-reap-complete` before emitting `STREAM-DEAD`, because that output costs the session its channel and the death marker alone is written before the reap runs. Each stall watcher can also lose the completion write and never retry it, so a marker more than 30 seconds old without its proof now yields `REAP-UNKNOWN` rather than an hour of waiting. Both watchers take the dispatcher's already-printed state directory through `IMPLEMENT_REVIEW_STATE_DIR`, keeping the round off a 30-second discovery window that a contended process launch can miss; discovery remains the fallback.

  Six review rounds went into this; the sixth returned `PASS`. Twenty-three mutation rows each turn a named test red, including one that restores the original defect.

- **A dispatched reviewer no longer spends its first shell spawns on the session banner.** Pairing every exec line in one review's state-directory tail with the runner verdict that followed it showed three of the round's twelve shell spawns going to the session-start banner: read the version cache, read both package manifests, read `AGENTS.local.md`, read the router skill, count the skills. The round reached its first actual review command on the twelfth attempt.

  The child was following the rules correctly. `AGENTS.md` states that the banner procedure overrides skill-first and task-first behavior, and the dispatched `developer_instructions` named only bootstrap and shared-configuration refresh. They now name the banner too. Nobody reads a dispatched child's terminal, so those spawns buy nothing, and on the machine in that report process creation was already failing intermittently with `STATUS_DLL_INIT_FAILED`.

- **A hook that inherits an open stdin no longer hangs the test suite.** `tests/test_session_bootstrap.py` let `session_bootstrap.py` inherit the test process's stdin, and the hook reads stdin to find the SessionStart payload's `source`. A handle that never reaches EOF makes that read block until the subprocess timeout fires.

  The failure looked like machine contention for two releases, because interactively the parent's stdin was already at EOF and the module finished in about 3 seconds. Run detached with nothing else on the machine, it took 634 seconds: seven timeouts at 90 seconds each and no slowness at all. A timing failure landing on an exact multiple of the timeout is a hang wearing a slowdown's clothes. The helper now passes `stdin=subprocess.DEVNULL`, which is what "no payload" should have meant, and the same detached run takes 5 seconds.

### Changed

- **`implement-review` states three rules a round used to fail without.** An Auto-terminal round is bounded by the calling agent's turn and the child writes its review once at the end, so a background dispatch that outlives the turn leaves no review while the dispatcher still exits 0. A bare `git diff --cached` over a broad staging area is charged to the child's context and can exhaust it outright. Both are now stated where a reader meets them before the decision they inform.

  Phase 1b gains a soft splitting rule: one pass is the default, split only when no shared contract crosses the boundary, and re-read that boundary while consolidating rather than assuming independence held. It also names which backends can honor a scoped diff command and states that the Claude backend cannot. The effort ratchet names its own cost: `xhigh` is the floor, and raising a round to `max` requires raising the per-tier timeout with it, 20 minutes at `xhigh` and 45 at `max`, against the Windows 600000 ceiling.

  `tests/test_skill_md_contract.py` moves three defects this loop produced repeatedly into the suite: a renumbered list left a duplicate item, a cross-reference stayed at the pre-insertion number, and the prompt template's hard-coded diff command was replaced in one place while four siblings kept the old form. The document is scanned once into an offset-preserving prose mask plus explicit fence spans, after four earlier drafts were each defeated on the round following the one that wrote them.

- **Two watcher test modules wait for their own evidence instead of sleeping.** One `stall-watch` test failed on both repositories on a single push, on `windows-latest . py3.12` only, and both went green on a rerun of that job with no code change. A local run then produced a third member of the family. Neither file needed a new idiom: `test_stall_watch.py` already had a `_wait_for` helper at eight call sites with three waits that had never adopted it, and `test_dispatch_codex.py` already had an inline deadline loop with one wait that had not.

  Green runs got faster, because a deadline loop leaves when the event arrives while a sleep always pays in full: 5.0s to 3.9s on the threshold test, 10.0s to 6.3s on the growth test. The fifth conversion is the one worth reading. A mid-transcript check slept and then asserted that no `stream-death` file had appeared, which is a false green: a watcher that never polled during the window satisfies that assertion without the classifier ever being asked. It now waits for a second `STALL` line, which is reachable only past the stream-death check.

## [0.7.16] — 2026-08-18

### Added

- **Bootstrap seeds the `todo/` drop box.** A person copies a file into `todo/`, points an agent at it with `@todo/<name>`, and the agent reads it, moves it to where it belongs in the repo, or deletes it; the resting state is empty. The convention was already in use across 22 repositories on one machine, spread by hand-copying, which is why it had reached neither a new project nor two of the existing ones. Every run now creates the folder and writes `bootstrap/todo-readme.md` into it when the README is missing, and adds the two `.gitignore` lines when they are absent.

  An existing README is never rewritten. One of those 22 carries a version written around its own filing rules, naming the case folders material gets routed into and the rename convention applied on the way out. Replacing that with the upstream copy is the same failure as replacing a composed `AGENTS.md` with the bare one, in a smaller file, so the seeding step creates and never overwrites. Deleting the file is what brings the upstream copy back.

  The pattern is `todo/*` paired with `!todo/README.md`, not `todo/`. Git cannot re-include a file whose parent directory is excluded, so the directory form silently drops the README and the folder then disappears from a fresh clone, which is the failure the convention exists to prevent. The two lines are appended together when the exclusion is missing, so the negation always lands after it. `AGENT_CONFIG_NO_TODO_DROPBOX` turns the whole step off.

  Both entry points gate the ignore rules and the ledger target on `todo/README.md` existing, rather than on the folder. `Test-Path 'todo'` is true for a plain file of that name where Bash's `[ -d todo ]` is false, so PowerShell used to record an ignore rule and a ledger target for a README that had never been written; the PowerShell seed also lacked `-ErrorAction Stop`, which let a non-terminating `Copy-Item` failure skip the warning and continue. A negation that already sits above a missing exclusion is repaired rather than documented as a known gap: the entry points compare the last matching line of each rule and append one canonical negation underneath when the order is wrong, and a run that finds the order already valid writes nothing.

  A linked `todo` is left entirely alone. Seeding through a symbolic link or a Windows directory junction writes the README into a directory outside the consumer repository during a session start, and git does not index it there, so the ignore rules would name nothing either. Both entry points skip the whole step when `todo` is a reparse point: Bash tests `-L`, which Git Bash reports for a junction as well as for a symlink, and PowerShell tests the `ReparsePoint` attribute, which both editions report. Two cases cover it, one where the link target is empty and one where a README already sits behind the link, because the seed and the postcondition gate are what fail in each.

  The README ships as one file rather than as a heredoc in each entry point, so the two cannot drift; `bootstrap/todo-readme.md` joins the cross-repo STRICT list for the same reason. Nine behaviors are covered end to end through all three entry points, and each one was checked by mutating the behavior and requiring its named test to go red. That check earned its place: the first version of the missing-source test asserted only that the README was absent, and the fixture helper reports an absent file and an empty directory identically, so a mutation that created `todo/` before checking for the template left the test green in all three entry points. It now asserts the directory's absence and the ledger's contents directly.

- **The bootstrap test timeout no longer fails on a busy machine.** One bootstrap run costs about 17 seconds on a Windows host when it is idle, because each fixture starts Git Bash or a PowerShell edition and the script spawns more from there. The cap was 30 seconds, under 2x that, so competing load turned a healthy run into `TimeoutExpired` and the failure read as a regression in whatever was being changed at the time. It did that three times across two releases: a CI job, a local full run, and a reviewer's own verification pass, and each diagnosis cost more than the cap ever saved. The nine call sites now share `SUBPROCESS_TIMEOUT`, 90 seconds by default and overridable through `AGENT_CONFIG_TEST_TIMEOUT` for a machine that needs more or a CI job that would rather fail fast. Measured on a loaded machine, the test that had just failed at the old cap completed in 39.7 seconds.

- **The consumer repo layout is written down.** Shared `AGENTS.md` gains a `Consumer Repo Layout` section naming what is tracked, what is generated, and who writes each path, so a new project inherits the conventions from bootstrap on its first session instead of from whichever older repo someone happened to copy. It states the three rules that are easy to get wrong: the three generated files are not tracked, `agent-config.yaml` uses the canonical `packs:` key rather than the deprecated `rule_packs:` alias, and `todo/` holds what a person put there rather than what an agent generated.

## [0.7.15] — 2026-08-18

### Fixed

- **Windows PowerShell 5.1 bootstrap runs composition and per-agent config generation again** ([#34](https://github.com/yzhao062/anywhere-agents/issues/34)). The sentinel rewrite in v0.7.13 passed `-c 'import sys; sys.stdout.write("...")'` to a native executable. Windows PowerShell 5.1 rebuilds native arguments as one command-line string and did not escape the inner double quote, so Python received a truncated program and raised `SyntaxError: unterminated string literal`. Every candidate interpreter then failed `Test-PythonRuns`, and `Find-RealPython` returned null. PowerShell 7 quotes the argument correctly, so tests that used only `pwsh` did not reveal the regression. On one machine, the same fixture reported `no Python 3 interpreter found` under `powershell` 5.1 and produced a healthy run under `pwsh` 7.

  The probe now uses a double-quoted PowerShell argument with single quotes inside the Python program, leaving no inner double quote for Windows PowerShell 5.1 to lose. A live regression test runs the actual function under every installed PowerShell edition, while a static test covers platforms without PowerShell.

- **The `/implement-review` interpreter probe carried the same defect.** `skills/implement-review/scripts/dispatch-codex.ps1` passed its probe the same way, so `Resolve-ProbedPython` rejected a working Python 3 under Windows PowerShell 5.1. With `ANYWHERE_AGENTS_PYTHON` set that became a hard exit; without it, every resolution tier failed and the reviewer dispatched with no resolved interpreter. Measured against a working Python 3.12: exit 1 and no output under 5.1, exit 0 and two lines under 7. The static guard for this defect class read only `bootstrap.ps1`, which is how a second instance in a different file survived; it now reads every `.ps1` in the repository.

- **No-Python bootstrap runs now report an omitted configured passive pack in real consumer repositories.** The Bash `_rule_packs_config_state` and PowerShell `Get-RulePacksConfigState` pre-parsers required list items below `rule_packs:` to be indented. YAML permits a block sequence at the same indentation as its key, and PyYAML's `safe_dump` emits that form. anywhere-agents uses `safe_dump` to write `agent-config.yaml`, so its reader classified its own writer's output as `empty`, the explicit opt-out. That classification suppressed the skipped-composition marker, left the ledger at `completed: true`, and suppressed the stderr tip. Measured on one machine, all 26 consumer checkouts carrying an `agent-config.yaml` parsed as `empty` and none as `nonempty`. The visibility machinery shipped in v0.7.13 and v0.7.14 had therefore never once fired in the field. Re-measured after this release, all 26 parse as `nonempty` through Bash and both PowerShell editions, and every answer matches the one `scripts/packs/config.py` gives for the same file. Twenty-five of the 26 are git repositories; the remaining one is a non-git backup copy.

The alias runs fine from a normal shell and fails only from Codex's spawn context, exiting `-1073741502` (`0xC0000142`, `STATUS_DLL_INIT_FAILED`), so a probe that executed it would report success and prove nothing. Both dispatchers now probe structurally: a PATH lookup, rejection of `WindowsApps` candidates and zero-length files, and no execution at all. A resolved interpreter is recorded and its absolute path is handed to the reviewer. When none is usable the reviewer is told not to shell out to `pwsh`, and the run continues. The probe warns and degrades rather than aborting, which is the opposite of the v0.7.9 Python-interpreter regression.

  Check 8 also stopped concealing the failure it exists to detect. When the review file was missing, the health check emitted `PASS check-8 tail-present-not-scanned` without reading the tail. That is precisely the case where the tail fills with repeated spawn failures while no review is ever written. Check 8 and Check 9 now have one implementation each, called from both the missing-review branch and the normal path. A missing review still hard-fails Check 1, while the tail and stall evidence get their real classifications. The signed-decimal NTSTATUS family `-107374\d{4}` joins the intrinsic failure patterns, and its own regex source joins the echo list so quoting the pattern in documentation cannot trigger it.

- **Drafts meant for copying elsewhere no longer arrive hard-wrapped** ([#27](https://github.com/yzhao062/anywhere-agents/issues/27)). The `AGENTS.md` rule asked for a fenced code block so text copies cleanly "with line breaks and formatting intact". Nothing said which line breaks belonged in the block. That stated reason read as an instruction to keep every one of them, including the ones added only so the draft looked right in a terminal. An email drafted this way pasted into Outlook broken at the agent's column and again at Outlook's.

  The rule now states that hard line breaks inside such a block are semantic. One paragraph or list item is a single unbroken line however long it runs, continuation lines are not indented, and the block is expected to look wide while it is being composed. Breaks that carry meaning, such as the lines of a postal address, are kept. The old rationale was replaced rather than contradicted, because leaving it in place beside a clause that disagrees with it is how a rule rots.

  A second bullet routes document-length drafts out of the terminal entirely. An email or a letter goes in a `.md` file whose path is named in the reply, since a terminal block that size is awkward to select and easy to truncate. This also names a mechanical fact the first rule left implicit. Markdown source pasted as plain text reaches Outlook or Gmail as literal `**` and `-` characters, because neither client renders markdown. Keeping bold, lists, and links requires HTML on the clipboard, which means copying from a rendered view rather than from the source. The rule now says to offer one when the formatting matters.

### Added

- **Prose writes are scanned by `agent-style`'s mechanical detectors, as an advisory.** When the `agent-style` package is importable, `guard.py` runs six of its deterministic rules (RULE-05, 06, 12, B, D, I) over prose writes, reports what they find, and does not block the write. The files covered are the ones the banned-word guard already reads: `.md`, `.tex`, `.rst` and `.txt`. Until now the rule pack reached consumers as text absorbed into `AGENTS.md` while its checker reached nobody. The CLI is not on `PATH` inside an agent session, and the `style-review` skill has to be invoked by hand. This puts the engine in front of every prose write for the cost of an import.

  These rules report rather than deny because they have no one-word substitution the way a banned AI-tell word does. RULE-12 fires on any sentence over thirty words. That is a mechanical fix while an agent drafts and a judgement call while a person types. A gate that blocked on it would be switched off within a day. Findings are capped at five plus a count of the remainder, since a wall of them is one the reader learns to skip. The pass runs only when the banned-word guard did not deny, so a blocked write still yields one message. It shares `AGENT_STYLE_HOOK` rather than adding an env var, and a missing or broken `agent_style` degrades silently, which is the default state in most repositories.

  Two choices came out of measurement rather than out of the documentation. The findings travel in `hookSpecificOutput.additionalContext` and in `systemMessage`. Probing Claude Code 2.1.229 showed those reach the model and the user respectively. Writing to stderr and exiting 0, the shape the banner re-arm advisory uses, reached neither. RULE-G, which asks for title-case headings, is left out of the set. Over the 155 markdown files in `agent-config` it produced 1018 of 2561 findings, and a 15-hit random sample contained nothing worth acting on. It flags the sentence-case headings that corpus writes on purpose. It also flags lowercase project names such as `agent-config`, which cannot be title-cased at all. `style-review` still runs it, where a human asked for the full audit.

- **Every bootstrap run writes `.agent-config/last-run.json`** ([#15](https://github.com/yzhao062/anywhere-agents/issues/15)). The sidecar records the phases the run completed and the files each one wrote. `completed: false` means the run stopped early, and `last_phase` names where. That is what a CI job or a resuming agent session needs in order to tell a partial bootstrap from a stale artifact. Both bootstrap scripts emit the same schema, with eight ordered phases from `start` to `finalize`.

  The ledger is best-effort and cannot fail an otherwise-good run. `bootstrap.sh` runs without `set -e`, so every helper returns success on its own rather than relying on error propagation. A `.agent-config` path that is unwritable, or already a regular file, simply skips the write. The document is replaced atomically through a temporary sibling, so an interrupted run cannot leave truncated JSON for the next session to choke on. The user-controlled upstream value is escaped before it reaches the document, and a test passes one containing a double quote and a backslash to prove the output still parses.

  A phase records a file only where the file was actually written. Targets are appended inside the same guards that do the copying, and the `generate` phase reports `skipped` when neither the composer nor the fallback generator ran, which happens when no Python resolves. An artifact built for audit that claims a file it never wrote is worse than one that stays quiet. Coverage stops at the bootstrap script: the wheel-side `pack verify` heal pass is recorded separately in `.agent-config/pack-lock.json`, and the sidecar says so.

## [0.7.11] — 2026-08-10

### Changed

- **Bootstrap no longer re-asks the network questions it already answered (issue #20).** A steady-state compose, one where every pack reports `unchanged` and no output content changes, went from 7.29 s to 3.88 s measured over repeated runs in a real five-pack consumer. Such a run still performs durable writes: active skill entries restage every file they own, and the composer always stages `AGENTS.md`, `pack-lock.json`, and the project `pack-state.json` (plus user state when nonempty). Permission entries are not part of that set, since they stage a settings merge only when the entry is newly created. That write set is where the durable-write cost noted below comes from. Bootstrap runs at every session start in every consumer, so this is latency the user feels every time.

  The cost was redundancy rather than serialization. Packs commonly share a source: the maintainer's consumers pin `profile`, `paper-workflow`, and `acad-skills` to the same repository at the same ref, so one identical cache key was sent to `git ls-remote` three times. The key is `(url, ref, explicit_auth)`: a caller that pins an auth method must be honored rather than served another method's result, so the snapshot guarantee below holds per key rather than per ref. The archive cache already deduplicated the clone, but it is keyed on the resolved commit, which is not known until after the resolve. Separately, every pack that walked the auth chain re-ran the `gh auth status` probe, which was about 1.8 s of the run spent re-asking a question whose answer cannot change mid-run. Deduplicating both brought `ls-remote` from four calls to two and the probe from 1.79 s to 0.43 s.

  Both caches are module globals that stay disabled until a compose run opens them through a context manager, so their active lifetime is one run rather than the life of the process. State that is live by default would outlast the run that wanted it: a long-lived process such as the CLI running verify and then compose would carry one probe answer and one resolved commit across both operations, and every test touching `fetch_pack` would inherit whatever the previous test cached. Running the suite proved the second half of that concretely, so the scope is the fix rather than a per-test reset. Nesting restores the enclosing scope on exit, including when the body raises.

  Both scopes are opened on the module objects the fetch path actually calls, which is less obvious than it sounds: `compose_packs` imports `packs.auth` while `packs.source_fetch` imports `scripts.packs.auth`, and those are two distinct module objects with independent globals. Opening the probe scope on the composer's own `auth` left the fetch path's cache empty, so the probe deduplication was inert and the measured gain came from ref deduplication alone. Reaching it through `source_fetch.auth` is what makes it real, and it is worth 0.75 s of the total. A test asserting only that a cache dict exists passes in both states, so the guard counts `subprocess` calls instead, and a companion test fails if the two import paths are ever unified so the reader is sent to the wiring rather than left to rediscover it.

  Scoping the resolve per run also closes a latent inconsistency, but only once the clone is allowed to correct it. A mutable ref can move between `ls-remote` and clone; `fetch_pack` already re-keys the cache slot to the post-clone commit in that case, and the run cache is now promoted to the same commit. Without that promotion the next pack sharing that cache key receives the stale pre-clone SHA, misses the slot just written under the post-clone SHA, clones the moving ref a second time, and the run can end holding two different commits for one cache key, which is the opposite of the snapshot property. Resolve failures are deliberately not cached, so a failing chain still reports the full per-method diagnosis on every attempt.

  What remains is not redundant: two genuinely distinct resolves (about 1.9 s) and the transaction's durable writes (`fsync` plus atomic rename, about 1.3 s across roughly 1080 file operations). Running the two remaining resolves concurrently would save about 0.7 s in exchange for thread-safety in the caches and concurrent writes into one archive-cache slot, which is a poor trade; weakening the durable-write path to chase the rest would trade a correctness guarantee for latency.

  **The digest encoding changed, and digests are now self-identifying.** Two independent ambiguities were found by reproducing collisions, not by reading the code.

  The pre-#18 framing joined `path + NUL + content + NUL` per file on the theory that paths cannot contain a NUL. Paths cannot, but file content can, so one file holding `b"x\0b\0y"` and two files holding `b"x"` and `b"y"` produced the same byte stream and the same digest; a directory swapped between those shapes passed `_delete_project_local` with no drift and was removed. Explicit 8-byte length prefixes close that.

  Joining the relative path into a single string was ambiguous in the other direction. On POSIX a backslash is a legal filename character, so a file literally named `a\b` normalized to the same string as file `b` inside directory `a`, and both hashed identically on a real Linux filesystem. Length prefixes did not help, because the collision happened before the framing. Paths are therefore encoded component-wise, from `PurePath.parts` on the real relative path rather than from splitting a joined string, so a separator never enters the byte stream for a filename to forge. Ordinary paths yield the same components on every platform, so digests stay identical across Windows and POSIX.

  Digests now carry their format: `dir-sha256-v2:<hex>` for the current encoding, and the bare `dir-sha256:<hex>` that shipped versions wrote.   Read sites accept the legacy digest as well, which matters where the source tree carried an artifact at copy time: that artifact is baked into the recorded value and was deployed alongside the real content, so the current form cannot reproduce it. This is not a gate bypass, because both branches are exact SHA-256 comparisons over the current tree. It is a compatibility **floor rather than a migration**: the legacy branch matches only while the tree is still byte-identical to what the old version copied, artifact included, so once that artifact is regenerated or removed neither form matches and the directory needs one successful compose to be re-recorded. `tests/test_dirhash_artifacts.py` covers the predicate, encoding uniqueness, legacy fidelity, the write-to-read round trip, the archive-root boundary, the drift gate, uninstall, and the archive cache's stricter rule.

Mismatch (or `new_content_sha256` missing) → keep the v0.5.2 reject behavior. `OP_DELETE` and the four non-unmanaged categories are unchanged.
- **Composer adoption logging (`scripts/compose_packs.py`).** After commit, when `Transaction.adopted_paths` is non-empty, the composer emits one stdout line — `ℹ composer adopted N pre-existing file(s) into pack-lock.json (content matched pack output):` — followed by the absolute paths in the same 2-space-indent style as the drift error. Silent adoption is avoided so the user sees what crossed the gate.

### Internals

- **`Transaction.adopted_paths`.** New instance attribute, initialized empty in `__init__`. Populated by `_validate_prestate` on every gate run; the same field is used by single-file collisions and per-file directory-handler scenarios (the `kind: skill` handler stages one op per file under `.claude/skills/<name>/`, so a 19-file skill that fully matches reports 19 entries).
- **Five new tests in `TransactionDriftGateTests`.** `test_unmanaged_collision_matching_content_adopted` asserts the new adoption path; `test_unmanaged_collision_mismatched_content_rejected` pins the negative case; `test_unmanaged_collision_partial_match_rejects_only_mismatch` covers the per-file directory scenario where some files match and some are user-edited; `test_adopted_paths_initialized_empty` and `test_unmanaged_no_collision_clean_install_no_adopt` pin the no-adopt baseline.

### Migration

- v0.5.2 users hitting the drift gate on AC→AA migration / interrupted `pack add` / team-clone first run / manual deploy can now upgrade to v0.5.3 and rerun the original command. No backup / move dance required when content already matches what the pack would write. ### Added

- **`scripts/packs/transaction.py` drift gate.** `Transaction.commit()` accepts an `expected_prestate` map keyed by absolute target path; each value is a `(category, recorded_sha256)` tuple. Five categories: pack outputs (recorded sha256 must match current), internal state files / composer-owned core / declared JSON merge targets (stage-time hash must equal commit-time hash — optimistic concurrency), and unmanaged (existing file → reject as collision; absent → allow). The composer builds the map after every staged write, before commit. Mismatches raise `DriftAbort` with a per-path reason; the staging dir is rolled back so no on-disk target is mutated. Empty `expected_prestate` (the v0.4.0/v0.5.0 default) preserves the previous behavior unchanged.
- **`scripts/packs/uninstall.py:run_uninstall_pack(name)`.** Single-pack uninstall path used by `pack remove`. Filters user-state owners by composite key `(repo_id, pack)` so two repos installing the same pack name from different upstreams don't decrement each other; computes remaining-output-claims from other lock entries before deleting shared outputs; preserves drift-safe retry semantics (any owned output whose hash drifted leaves the pack's lock + state ownership records intact). File-like user-level outputs follow the empty-owners-AND-hash-match delete rule; active-permission entries only prune state-side owner records and never touch `~/.claude/settings.json` (JSON unmerge stays out of v0.5.2 scope).
- **Lock schema fields `latest_known_head` + `fetched_at`.** Both optional. Composer populates them at fetch time (head equals `resolved_commit` because the fetch just happened); `pack verify` updates `latest_known_head` later. Old locks without these fields parse cleanly and contribute zero to `update_count`.
- **`compose_packs.py uninstall <name>` mode.** New subcommand on the composer subprocess that drives `run_uninstall_pack`. Used by `pack remove`. Composer self-locks; the CLI does not hold outer locks across the subprocess invocation.

### Changed

- **`pack add` behavior split**. Outside a bootstrapped project (no `.agent-config/repo/scripts/compose_packs.py` and no bootstrap scripts in `.agent-config/`) the CLI registers user-level only and prints `ℹ Registered globally. Run anywhere-agents in a bootstrapped project to deploy.` In-project the CLI also writes `agent-config.yaml` and invokes the composer.

### Internals

### Migration

## [0.1.0] — 2026-04-16

Initial public release. The sanitized downstream of the author's private daily-driver agent config, refined over months across many repositories, machines, and workflows. This release covers both the GitHub repo content (bootstrap, skills, guard hook, settings, tests, docs) and the matching PyPI / npm CLI packages.

### Added — repository

- **Bootstrap** (`bootstrap/bootstrap.sh`, `bootstrap/bootstrap.ps1`) — idempotent sync scripts for macOS, Linux, and Windows. Fetch `AGENTS.md`, sparse-clone skills, merge settings, deploy the guard hook, update `.gitignore`. Safe to run every session.
- **`AGENTS.md`** — opinionated agent configuration covering:
  - Source-vs-consumer repo detection.
  - Session start checks (OS, model and effort level, Codex config, GitHub Actions version pins).
  - User profile placeholder (intended for customization in forks).
  - Agent roles (Claude Code implementer + Codex reviewer).
  - Task routing via `my-router`.
  - Codex MCP integration guide.
  - Writing defaults (~40 AI-tell words to avoid, punctuation rules, format preservation).
  - Formatting defaults, Git safety, shell command style.
  - GitHub Actions version standards (Node.js 24 minimums).
  - Environment notes.
  - Local skills precedence and cross-tool skill sharing conventions.
- **Skill: `implement-review`** — structured dual-agent review loop with content-type-specific lenses (code via Google eng-practices, paper via NeurIPS/ICLR/ICML, proposal via NSF Merit Review or NIH Simplified Peer Review), focused sub-lenses (code/security, paper/formatting, proposal/compliance, etc.), multi-target reviews, round history tracking, and reviewer save contract. Includes example reviews covering code, paper, and proposal tracks.
- **Skill: `my-router`** — context-aware skill dispatcher shipped as a template. Ships with `implement-review` as the only concrete routing rule plus an extension template so users register their own skills in a fork.
- **Guard hook** (`scripts/guard.py`) — PreToolUse hook that intercepts destructive Git and GitHub commands (`git push`, `git commit`, `git reset --hard`, `git merge`, `git rebase`, `gh pr merge`, `gh pr create`, etc.) and compound `cd <path> && <cmd>` chains with deliberately memorable warnings ("STOP! HAMMER TIME!", etc.) to prevent muscle-memory auto-approval. Tuned to keep read-only operations fast. Shell deletes (`rm -rf`) go through Claude Code's built-in permission prompts via the user-level `ask` settings, not the guard hook itself.
- **Claude Code commands** (`.claude/commands/`) — pointer files for both shipped skills (local-first, bootstrap fallback lookup).
- **Claude Code settings** (`.claude/settings.json`) — curated project-level permissions.
- **User-level settings** (`user/settings.json`) — permissions, guard hook wiring, and `CLAUDE_CODE_EFFORT_LEVEL=max` env default.
- **Tests** (`tests/`) — bootstrap contract validation, skill layout checks, settings merge preservation, and Windows + Linux bootstrap smoke tests running in GitHub Actions CI.
- **CI** (`.github/workflows/validate.yml`) — validation on `ubuntu-latest` and `windows-latest` with `actions/checkout@v6` and `actions/setup-python@v6`.
- **README** with problem framing, "What you get" benefit list, install paths (PyPI / npm / raw shell), day-to-day usage notes, collapsible reference sections, and maintainer context. Includes a hero image (`docs/hero.png`, with `docs/hero.html` source and a vendored avatar at `docs/avatar.jpg`), a Mermaid review-loop sequence diagram, the "agentic workflow this encodes" educational section, and GitHub-style `> [!NOTE]` / `> [!TIP]` callouts.
- **`CONTRIBUTING.md`** — scope and process for PRs, bug reports, and customizations (customizations go in a fork; upstream takes bug fixes and clear improvements).
- **`LICENSE`** — Apache 2.0.

### Added — packages

- **PyPI `anywhere-agents` 0.1.0** — installable via `pip install anywhere-agents` or `pipx run anywhere-agents`. Ships a thin CLI (`anywhere_agents.cli:main`) that downloads the latest shell bootstrap from the repo and runs it in the current directory. Supports `--dry-run`, `--version`, `--help`.
- **npm `anywhere-agents` 0.1.0** — installable via `npx anywhere-agents` or `npm install -g anywhere-agents`. Same behavior as the PyPI CLI, implemented in Node.js.
- **Agent-native install path**: users can tell their AI agent _"install anywhere-agents in this project"_ and the agent will pick whichever command (pipx, npx, or raw shell) matches the environment. The packages exist purely as agent-friendly entry points; install logic stays single-source in the shell bootstrap scripts.

### Not included (out of scope for 0.1.0)

- No YAML manifest or config file — files in the repo are the configuration.
- No selective-update tooling — Git is the subscription engine (`git pull upstream main`, `git cherry-pick`).
- No environment auto-install — `AGENTS.md` documents required tools; users install them.
- No multi-agent expansion beyond Claude Code + Codex — forks can add Cursor, Aider, Gemini CLI support.
- No profiles system — there is one configuration; forks are how other "profiles" exist.
- No marketplace, registry, or web UI.
